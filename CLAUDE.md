# concall-alpha — agent guide

Next.js 15 / React 19 portal that reads concall analysis from Supabase and renders company pages, leaderboards, and sector views. Sibling app [concallyser/](../concallyser/) produces the data; this repo only consumes it.

## 30-second architecture

- `app/` — Next App Router. Company page is `app/company/[code]/`; section components live in `app/company/components/`.
- `lib/<domain>/` — per-section data layer. Each domain folder has `types.ts` (frontend payload validation) and `normalize.ts` (raw → display shape). Domains: `business-snapshot`, `moat-analysis`, `growth-outlook`, `guidance-snapshot`, `guidance-tracking`, `key-variables-snapshot`, `sector-intelligence`, `company-industry-analysis`.
- `lib/<top-level>.ts` — cross-cutting utilities not scoped to one domain. Examples: `admin-auth.ts`, `company-overview-cache.ts`, `company-freshness.ts`, `visitor-id.ts`, `logger.ts`, `utils.ts`, `nse-event-calendar.ts`, `homepage-activity-feed.ts`, `leaderboard-rank.ts`.
- `lib/supabase/` — Supabase clients (`client.ts`, `server.ts`, `middleware.ts`, `admin.ts`, `public-read.ts`) plus `*.sql` files that define the portal-owned tables.
- `components/ui/` — shadcn/ui primitives. `app/company/components/surface-tokens.ts` is the shared surface-class source.

## Source of truth rules

The cross-cutting rules in [../CLAUDE.md](../CLAUDE.md) (schemas-as-authority, versioned-root-wins, schema-valid-vs-framework-faithful, never-copy-from-peer-rows) apply here in full. Concall-alpha-specific additions:

- **`lib/<domain>/types.ts` is the frontend's own validation gate.** It must accept everything the schema accepts and reject what the schema rejects. If you change one, change both.
- **Derive `lib/<domain>/types.ts` from the schema**, not from a Supabase row — same reasoning as never-copy-from-peer-rows.

## Verify before claiming done

In order of cost:

```bash
npm run lint        # fast
npm run typecheck   # medium speed; catches type drift
npm run build       # full Next build, slow but catches RSC / route-level issues
npm run perf:cls -- http://localhost:3000   # mobile CLS probe for /company tab swaps (after `npm run build` + `next start`; needs a Chrome binary or CHROME_PATH). Re-run whenever section-loading, section-skeleton, deferred-company-sections or company-page-workspace change.
```

For UI changes: run `npm run dev` and exercise the change in a browser. Type-check passing is not the same as feature working — say so explicitly if you couldn't browser-verify. Mobile layout is part of the check (the section SKILL spells this out).

## Don't touch without asking

- `lib/supabase/*.sql` — these are applied **manually** in the Supabase SQL editor. Editing them does not migrate the live DB. If a column is missing in production, the fix is to apply DDL in Supabase + run `notify pgrst, 'reload schema';` (PostgREST caches schema).
- `SUPABASE_SERVICE_ROLE_KEY`-backed code paths (`lib/supabase/admin.ts`, `app/admin/`) — these read across users. Don't broaden their use.
- `data/input/` does **not** live in this repo; it's owned by `concallyser/`. Don't add scripts here that write to it.

## Adding a new analysis section

Reference implementation: `moat-analysis`. Files to copy/adapt:

1. Schema in `/schemas/<name>_v<n>.json` (or use existing `concallyser/schemas/<name>.schema.json`).
2. `lib/<name>/types.ts` — TS types + a validator that mirrors the schema.
3. `lib/<name>/normalize.ts` — normalize raw Supabase row → display shape.
4. `app/company/components/<name>-section.tsx` — UI. Use `SectionCard`, `surface-tokens.ts`, and the drawer-vs-details rules from the SKILL below.
5. Wire into the company page (see how `moat-analysis-section.tsx` is wired in `app/company/[code]/`).

Before pitching or scoping a new feature, section, or surface, walk the four phases in [skills/concall-alpha-feature-planner/SKILL.md](skills/concall-alpha-feature-planner/SKILL.md). It produces a one-page brief that hands off to `/plan-eng-review` and `/ship`.

Read [skills/concall-alpha-ui-patterns/SKILL.md](skills/concall-alpha-ui-patterns/SKILL.md) before any company-page UI change. It has the section hierarchy, drawer vs details rules, and review checklist.

## Project-specific gotchas

- **Every `concall_analysis` query must filter `.not("details->scoring_meta", "is", null)`.** Rows without `scoring_meta` were scored under retired pre-deterministic logic and are misleading; they are hidden portal-wide (decision 2026-06-12) but kept in the DB as the re-score backlog. If you add a new query, carry the filter.

- **Every discovery surface must filter through `isDiscoveryListed` ([lib/coverage-policy.ts](lib/coverage-policy.ts)).** Coverage is a curated ~100 mid/small caps: companies admitted as large cap (`market_cap_band_at_admission = 'large'`) and those below the composite cut (`excluded_from_discovery`) are de-emphasized — off leaderboards/homepage/sectors, but their pages stay reachable **and searchable**. Select the columns via the shared `COVERAGE_SELECT` and pass the whole row to `isDiscoveryListed(company)`. NULL band = covered (fail-open). **Search (`lib/company-search-cache.ts`) and watchlists are deliberately unfiltered** — search is navigation, watchlists are user-owned.
  - The leaderboard has **four** company substrates, not two: `getConcallData()` (quarter board + Trend) is separate from `fetchLeaderboardData()` (growth + moat), plus the activity feed and the hero stats. A "hide these companies" change that only touches `data.ts` silently leaks them into the quarter/Trend board. `getConcallData({ excludeLargeCaps: true })` is opt-in for that reason.
  - **The two gates are separate predicates, and the Overall board needs them apart.** `isAdmittedLargeCap` removes a company outright; `isBelowCoverageCut` only greys it out — the Overall board renders the below-cut tail dimmed (still linked; de-emphasized, not blocked — decision 2026-08-01 after a replay showed rage clicks on the dead names) rather than dropping it (`getConcallData({ excludeLargeCaps: true, includeBelowCut: true })`). `isDiscoveryListed` is still the right call for every other surface; reach for the two halves only when a surface treats them differently.
  - **The Overall board and a watchlist are one component** ([components/score-board-table.tsx](components/score-board-table.tsx), rows built by [lib/score-board-rows.ts](lib/score-board-rows.ts)). They differ by two props only: `watchlistId` turns on the Remove column, and `belowCut` greys a row — never set on a watchlist, which is user-owned and unfiltered. Trend, Moat Tag and mgmt guidance are on neither: a delta and a categorical rating can't share the number+band format, so they keep their own leaderboard tabs. Change the board once, not twice.
  - **The Overall board's `#` column is derived from its Read column, not from stored `coverage_rank`.** `coverage_rank` is written by a reviewed manual step, so between runs it can contradict a Read computed live from the current legs (the first build showed rank 6 carrying a higher Read than rank 1). The stored value still governs **which** companies are greyed; the ordering is computed. `lib/board-read.ts` mirrors the pipeline's weights and is pinned to them by `tests/board-read.test.ts` against a full-precision fixture — if you change the weights, change them in `compute_composite_score.py` first, re-run it, and regenerate the fixture.
    - **The live board quarter LEG deliberately differs from the cut's (2026-08-11).** The Overall board ranks on a *recency-weighted* 4Q leg ("latest counts double", `lib/quarter-composite` `blendQuarterLeg`, exposed as the row's `Latest 4Q Blend`), while `compute_composite_score.py`'s coverage cut stays on the flat 4Q mean. Recency lives in the live ordering; membership stays stable. Only the quarter INPUT diverges — the weights (0.88/0.12) and composite arithmetic still mirror the pipeline and stay fixture-pinned. This is safe only because the greyed-tail pin holds greyed rows at the bottom regardless of their live Read. Every live Read (board, sectors, watchlists, themes, company-page overview, homepage hero) takes its quarter leg from the blend (`blendQuarterLeg` / `blendQuarterLegFromSeries`); the flat `Latest 4Q Avg` is display-only (the "4Q" column) and the cut. A `mean4Q*` call feeding `classifyBoardRead` is the recurring bug (2026-08-04, 2026-08-11, 2026-09-19).
  - Ranks (`quarter_rank`/`growth_rank`/`sector_rank` in the overview cache) are computed **within the covered universe only**; an excluded company gets null ranks and its page omits them.

- **Verifying coverage counts:** PostgREST `neq.large` silently drops NULL-band rows, so it under-counts. Mirror `isDiscoveryListed` in JS instead, or you'll "confirm" 98 when the portal shows 100.

- Industry Context is a company-page tab (after Business Snapshot) — one section, one fetch (`getCompanyIndustryAnalysis`, `cache()`-wrapped). **Redesigned 2026-09-21** (`industry-context-section.tsx`) to fix a text-heavy wall: a verdict hero (industry name + `customerNeed` + the company's own market-share tiles), a **margin-first value-chain rail** (per-layer detail — revenue model, participants, roles — behind a right Drawer), **sub-sector cards** (side-by-side, one per sub-sector), and Types-of-players / Regulations behind drawers. Each sub-sector card surfaces `capital_cycle` (via `getCapitalCycleDisplay` in `[code]/display-tokens.ts` — a toned chip + Down→Late position rail, with a dashed "Mixed signals" state), the company's share chip, tailwinds/headwinds, and a per-card "Market map & supply-side" drawer (ranked player bars + supply-side + evidence-pack read). The old standalone Sub-sectors section was already retired earlier; **the tabbed `SubSectorTabs` + `sub-sector-entries.ts` were also removed** — the section now merges `company_fit.qualifyingSubSectors` with `subSectorCards` inline (same merge, but carrying tailwinds/headwinds too). `sub-sector` id stays dormant in `constants.ts`/`SHORT_LABELS`/`section-card.tsx`. 100% data-driven (no producer prose synthesized in the portal); company↔player share matching is a deterministic ticker/name match that keeps the parenthetical owner. Dev preview: `/dev/industry-context?company=<CODE>`. Not sign-up-gated (Industry stays open).
- Business Snapshot renders **expanded by default** on the company page. The internal `<details>` blocks inside it (about "Read more", historical-economics drawer) are intentional *sub-element* collapses — don't flatten them.
- The Guidance section (`guidance-history-section.tsx`, id `guidance-history`) shows **two verdicts** when the snapshot carries the forward-strength layer (`details.forward_strength`, from `/guidance-deep-track`; schema `/schemas/guidance_strength_v1.json`, parsed by `parseForwardStrength` in `lib/guidance-snapshot/types.ts`). Order then: (1) **"How strong is the guidance right now?"** — the forward-book verdict, ambition × evidence pills + headline; (2) **This year / Long-term** cards (2026-09-18) — the live book split by when each commitment comes due (`lib/guidance-tracking/horizon-split.ts`: due ≤ Q4 of the current FY → This year, later → Long-term, standing/rolling/unreadable horizon → a collapsed "Ongoing" list). These cards ARE the watch list on this layout: each holds its own ranked clickable rows (top 3, rest behind a toggle; order = `compareMaterialityKeys` in `verdict.ts`: deadline FY → consolidated before segment → **what just moved** → revenue before margin → quarter precision → trail depth → key) so every live commitment appears exactly once, plus the order-backed/asserted/aspiration count **of the rows on that card** — `evidence_class` lives on `guidance_tracking.details`, not on the snapshot's `guidance_items`, so the panel joins it in by `guidance_key`; the snapshot is a curated subset of the full live book, which is why the scorer's "OF N LIVE" total is no longer shown beside it; (3) **"Should you believe any of it?"** — the credibility verdict + resolved track record; (4) the Guided / Delivered / Outcome table of resolved ones, truncated to 5 with a "show all" — sorted by **latest mention** (not horizon), a miss ahead of a win on a tie, because met-first truncation hid the misses on the one section that exists to surface them. **"The strategy behind the numbers" (`details.strategy_narrative`) now renders on the Growth tab as its "Growth engine" card** (`strategy-narrative-card.tsx`), beside a templated **Growth summary** (`lib/growth-outlook/summary.ts` — base case + bear/bull range, bridged earnings, top catalyst; the LLM `summaryBullets` no longer render); both panels read the snapshot through the one `cache()`d `lib/guidance-snapshot/get.ts`. Snapshots WITHOUT the forward-strength blocks keep the original **credibility-first** order (verdict card + track record on top, then the ranked "What to watch" cards). Ambition (`ambitious`/`measured`/`conservative`) and the two strength narratives come from the deep-track producer; the credibility tier, the live-state chips, and every resolved number are still templated in `lib/guidance-tracking/verdict.ts` from `guidance_items` — the Delivered column reads ONLY the outcome trail step (`met`/`missed`), never a number parsed out of `status_reason` prose. Per-thread trails stay thread-style inside the row Drawer; don't reintroduce comparison cards. A revision on a commitment whose horizon is still ahead is **live**, not graded (shared with the Overview's Walk-the-talk count via `isGradedForTier`).
- `/admin` requires both `ADMIN_PANEL_PASSCODE` and `SUPABASE_SERVICE_ROLE_KEY`. If a feature seems to "not work locally," check `.env.local`.
- `lib/supabase/*.sql` files exist beyond the four named in the README (e.g. `homepage_activity_feed.sql`, `company_page_overview_cache.sql`, `activity_feed_score_history_indexes.sql`). Treat the README list as incomplete; check the directory.
- **`page_view_events.referrer` changed meaning 2026-07-17.** It now stores the client-reported external referrer (null = internal/direct); rows before that date hold the route's own Referer header — always the app itself — and are **not** acquisition data. Classify via `lib/attribution.ts` (`isInternalHost` treats all `*.vercel.app` as internal). Tracker payload fields beyond `path`/`companyCode` must stay optional (old cached bundles POST without them).
- **PostHog** initializes in `instrumentation-client.ts` (browser-only, silently off when `NEXT_PUBLIC_POSTHOG_KEY` is empty) and is reverse-proxied through the `/ingest` rewrites in `next.config.ts`. `skipTrailingSlashRedirect: true` and the `ingest` exclusion in `middleware.ts`'s matcher both exist for this — don't remove either.
- **Canonical origin comes from `NEXT_PUBLIC_SITE_URL`** via [lib/site-url.ts](lib/site-url.ts) (metadataBase, sitemap, robots, canonicals). It's a Vercel env var, not code — never hardcode the domain, and never use `VERCEL_URL` for anything canonical (it's the per-deployment preview URL).
- **No `useId` inside components loaded through `next/dynamic`** (the leaderboard boards in `app/leaderboards/tables-lazy.tsx`, the lazy sections). The loadable's Suspense boundary sits at a different depth on the server and the client, so the generated ids differ and React logs a hydration attribute mismatch on every load. Label form controls by nesting or with a static id. Check `browse console --errors` at 390px after touching those components — the Next dev overlay's "N issues" badge is the only visible symptom.
- **Phone layouts for wide boards live in the same component as the table** (`components/score-board-table.tsx`, `app/sectors/page.tsx`): a `<ul>` below `lg`, the `<table>` from `lg`, both server-rendered and CSS-toggled, then the hidden one unmounted via `hooks/use-min-width.ts` once matchMedia has answered (`null` on the server so hydration matches). See "Responsive Behavior → Mobile" in [docs/portal-design-system.md](docs/portal-design-system.md). Server-rendered sections use the same gate through `components/viewport-gate.tsx` (`BelowSm` / `FromSm`) — `/desk` is one tree whose blocks are flex-`order`ed on the phone (change-first: Featured → activity → ranking), never a second page tree. `/announcements`, `/themes`, `/leaderboards`, `/sectors` (2026-09-13) and the Journal index `/blog` (2026-09-22; `app/blog/journal-phone.tsx`) paint a house-skin phone tree beside their untouched desktop tree (`BelowSm className="house"` / `FromSm`) from one data fetch — the SSR HTML carries both until matchMedia answers (deliberate: no layout shift, one fetch; a later breakpoint crossing re-mounts the other tree from scratch, so keep shared state in the parent, not the paint — the Journal's view state, `app/blog/journal-view-state.tsx` (Notebook filter + stories fold), is the reference: one context above both paints) — built on the primitives in `components/mobile-card.tsx` (card, whole-row link, chip grammar, masthead, crest). The Journal post page `/blog/<slug>` (2026-09-23) stays one tree and gates only its poster figure (`app/blog/post-image.tsx`: full width from `sm`, a tappable strip that opens the full image below — same `src` in both paints, never `priority` on the hidden one). The phone "app" chrome — compact top bar in `app/(hero)/navbar.tsx` + `components/mobile-tab-bar.tsx` in the root layout — is keyed on the phone-app routes via `lib/phone-chrome.ts` (four direct tabs Desk / Filings / Ranking / Journal, plus Themes and Sectors behind the fifth "Other" tab, a bottom sheet that also carries Watchlists when signed in and the Telegram link); add a route there, not in the components.
- **Sign-up gate on company tabs (`SIGNUP_GATE=on`, server-read; unset + redeploy = off).** Logged-out readers get six tabs (Business, Quality, Variables, Growth, Valuation, Guidance) clipped at that section's single `data-gate-cut` element behind a free sign-up card; Overview, Announcements, Industry and Quarterly stay open. Server half `gated-panel.tsx` (inside the panel's Suspense, auth via the `cache()`d `lib/supabase/auth-state.ts`), client half `section-depth-gate.tsx`; rules, the per-tab "below" copy and the clip maths live in `lib/signup-gate.ts`. If you restructure a gated section, keep exactly one `data-gate-cut` on a real DOM element in its main stack and update that tab's "below" lines in the same PR. No marker = no gate (never guess a clip height — it shifted the lazy Guidance tab). Copy rule: "Free to read. No card, no trial.", never "free forever". Verify with `npm run probe:gate -- http://localhost:3000` (and `--expect off`), then `npm run perf:cls`. **Journal posts gate too (2026-09-25)**, same flag and card (`scope="post"`): the cut is derived by `gatePost` (`app/blog/related.ts`) — before the first `## 1.` heading, else the heading after "At a glance", else the second `##`; fewer than two headings, or no prose above the cut, = no gate — and the card lists the next hidden headings. Decided on the server in `app/blog/[slug]/page.tsx` via the same `getIsAuthenticated()` — posts render per request (the root layout reads the session; the build's "●" for `/blog/[slug]` is misleading, production serves `no-store`). The marker div (`#continue-reading`) is the sign-up return anchor. Events carry `section_id: "journal"` + `post_slug` and no `company_code` (so they stay out of per-company gate funnels), through to `signup_completed`; `journal_read_complete` carries `gated` (leave `gated: true` out of believer-cohort reads — the scroll reached the card, not the post's end). Verify with `npm run probe:journal-gate`.
- **Quality tab (2026-09-23) replaced the Moat tab** — section id `quality` (`#moat-analysis` and its sub-anchors still resolve via `LEGACY_SECTION_IDS` in `lib/section-hash.ts`). `quality-section.tsx` stacks five SectionCards: Financials, Returns & margins, Moat (the old `moat-analysis-section.tsx` reshaped into one card with a collapsed Full analysis), Ownership, Forensic checks. The four data cards read one `company_quality` row (`lib/company-quality/`, schema `/schemas/company_quality_v1.json`, produced by `concallyser/scripts/scrape_screener_quality.py` from Screener — deterministic, no LLM); the moat card reads `moat_analysis` as before, so either feed can be absent on its own. **Every forensic status is a threshold rule in `lib/company-quality/forensics.ts`** (closed vocabulary Clean / Watch / Flag; `not_assessed` = needs the annual report, `not_applicable` = bank/NBFC statement model — both muted and out of the tally, never Clean). "What happened" / "The read" copy is templated from the numbers in `reads.ts`; a producer may override through `payload.reads.*`. The gate cut sits on the Returns card, or on the moat's Full-analysis block when no substrate row exists. Dev preview: `/dev/quality?company=<CODE>` reads `/tmp/sandbox_quality/<CODE>.json` (`&source=live` reads the promoted row).
- **Share cards are site-wide via `app/opengraph-image.tsx` / `app/twitter-image.tsx`** (branded 1200×630). Per-route metadata composes with them — Journal posts add OG `article` + Article JSON-LD in `app/blog/[slug]/page.tsx`. If you set `twitter` metadata on a route, keep `card: "summary_large_image"`; plain `"summary"` silently downgrades shares to a small thumbnail.
- **Journal post page (`app/blog/[slug]/page.tsx`, 2026-09-23) has a build-time contract for post authors.** A company post's poster `<figure>` is lifted out of the MDX by `liftPoster` (`app/blog/related.ts`) into `<PostPoster/>` before next-mdx-remote compiles it, and a poster figure the lift cannot read fails the build — keep it to one `<img>` with a double-quoted `src` (and `alt`, if given — it defaults to empty), no `>` inside `alt`, and a `src` matching `/blog/<code>-story-<date>.png` (`.jpg`/`.jpeg` also pass). The byline's read time and the "Next read" block are derived (`readMinutes` / `nextReads`: a company's other stories, then comparisons whose body links its `/company/<CODE>` page; a Notebook post gets the newest in its category), never hand-curated per post.
